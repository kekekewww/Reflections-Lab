# Device hearing V3: preparation and use

V3 is a versioned adaptation of `../device-hearing/manual-probe-driver.mjs`; the original hearing protocol remains authoritative for user actions, commands, limits, safety and disposition. Differences: exact frozen product manifest and bundle (175 inputs, 14 bundle files) replace the older UI manifest and rebuilt comparison; no timestamp changes are accepted. The frozen bundle is served from the cache, and all listed current inputs and verified HTTP bytes must still match. Every session checks driver, adapter, binding, manifest, bundle, helper and review bytes again during export. The original historical helper review does not independently approve V3. Root must independently review V3 before any human session.

After independent review, use two PowerShell terminals from the repository root. First run `node tests/browser/device-hearing-v3/serve-frozen.mjs`; keep it running, and note the printed PID. In the second terminal run:

`node tests/browser/device-hearing-v3/manual-probe-driver.mjs --go --binding tests/browser/device-hearing-v3/binding.json --base-url http://127.0.0.1:5174/ --preview-pid <PID_FROM_FIRST_TERMINAL> --browser-executable "<ABSOLUTE_CHROME_EXE>"`

The coordinator supplies the actual PID and browser path, then follows `../device-hearing/manual-probe-protocol.json` stages and JSON line commands. Start with low physical volume. Maximum session is 30 minutes; 64 command lines, 16 snapshots, 15-second HTTP check, 8 MiB per asset and 64 MiB total. The user performs listening actions; the driver never infers hearing or device route. On finish choose explicit `{"command":"finish","browser":"close"}`; only if the user explicitly requests a retained tab choose `keep`. Stop the owned server separately after the session. Failed preflight or cleanup must be preserved, not bypassed. Do not use a new build with this fixed binding: it requires a separately reviewed new binding.

`node --test tests/browser/device-hearing-v3/*.pure.test.mjs` runs host pure tests. `node tests/browser/device-hearing-v3/qualify-no-audio.mjs` runs an owned local HTTP server and headless browser with AudioContext construction denied and arm blocked; it does not run a hearing test. A local network permission may be required. Actual browser device route, native callbacks and human listening remain NOT RUN until observed.

The frozen bytes now live in `artifacts/v1/device-hearing-v3-frozen-20261029-r6/`. Before human use the driver requires `independent-review.json` there, authored only after Root independently reviews the full execution closure. The closure includes this driver, its gate and adapter, binding, server, original protocol, helper and test, historical helper review, native launcher, raw manifest and every frozen output. Missing, mock or changed review data fails closed; exports recheck it. The receipt is separate from the closure to avoid a circular hash. The frozen distribution remains subject to the final NOTICE/license review documented in the artifact's PROVENANCE.md.

The human session permits only `C:\Program Files\Google\Chrome\Application\chrome.exe`, SHA-256 `480f275b63d1ea39113cbc8344ac395578acc25b432bd39af5fbc77005179aca`; the driver reads and records the executable hash before launch and rechecks it on export. The no-audio qualification accepts only Playwright's `chromium.executablePath()` and places its actual path and hash in the explicitly mock fixture; this does not approve that binary for a human session.
