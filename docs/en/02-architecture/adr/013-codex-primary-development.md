# ADR-013: Codex Leads Development; Muse Code Is Optional

- Status: **Accepted, 2026-10-27**, based on the [explicit user requirements](../../00-project/SOUND_BEHAVIOR_REQUEST.md) in this round.
- Decision: Codex is responsible for architecture, implementation, task progress, and quality validation; Skills / Subagents and authorized Goals may be used. Normally, work directly from Wiki tasks / formal specifications without first creating a cross-coding-agent run or launching Muse.
- Supersedes: ADR-012's “Muse Code preferred / mandatory Codex→Muse→Codex flow” and priority switchback policy after quota recovery. ADR-012's independent validation, bounded retries, workspace mutual exclusion, budget / provenance, and security boundaries remain reusable principles.
- Muse Code: **Optional**. Select it only when it adds concrete value to the task and user authorization and resource conditions are met; the user has confirmed the current Muse balance is 0, so no model work may be dispatched. Retain `scripts/agents`, `schemas/agents`, `prompts/muse`, and historical Phase3 tests as an optional Harness; their MUSE default describes only that legacy tool profile, not this project's current development default. Completing the main product no longer requires validating Live Muse or its SDK first.
- Product AI: The Meta Muse Agent still uses Meta Model API to plan scenes, physics / Sound Behavior, and experiments; the model does not execute arbitrary code or fabricate measurements. Using Codex for development is not evidence of product Meta integration; check competition rules separately in the [current official terms record](../../01-compliance/HACKATHON_RULES.md).
- Verification: Prioritize fixed tests, deterministic benchmarks / references, CI, and isolated review. When Codex both writes code and explains the results, its own claim of success cannot count as independent validation; explicitly disclose browser / audio / Meta live checks that have not been run.
- History: Do not rewrite Phase3 artifacts / completed Task0008; the original Live Harness Task0009 is downgraded to a canceled mandatory task, with its rationale retained, and is not a product dependency. Product account / eligibility Task0007 remains separately tracked and does not disappear when the Muse development requirement is canceled.
- Rationale: The product has not yet been implemented and competition time is limited; remove a cross-coding-agent process that yields no benefit and spend the time on testable vertical product capabilities.
- Trade-off: Using a single primary coding agent still carries correlated risk, controlled through independent processes / references / review; do not assume that changing a model name alone increases validation credibility.
