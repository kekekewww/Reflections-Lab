# ADR-014: Separate Sound Behavior from Physics / Propagation

- Status: **Accepted for architecture, 2026-10-27; product implementation pending**. Sources: [User requirements](../../00-project/SOUND_BEHAVIOR_REQUEST.md), [Research](../../10-sound-behaviors/SOUND_BEHAVIOR_RESEARCH.md), [Architecture](../../10-sound-behaviors/SOUND_BEHAVIOR_ARCHITECTURE.md).
- Decision: Adopt **declarative Event Rules + orthogonal State Machine**, with the Inspector as the primary authoring interface. States come from normalized Physics / Player events; rules select content, curves, and logical instances; every 3D emitter passes through the same Custom Acoustic Core and Web Audio renderer. The Graph editor and modal synthesis are P2, with no new mandatory middleware dependency.
- Separation: Rigid-body motion / contacts, sound content, and acoustic media / surfaces each have their own authority. Replacing an impact with piano sound does not change mass/friction or wall absorption; sample presets are labeled perceptual approximation / Creative and cannot be called natural vibration simulation. Gravity0 is not vacuum; mechanical collisions still occur in vacuum, but this version does not simulate sound transmission through solids.
- Physics: OnThrow / OnDrop come from successful explicit interaction intents; impact requires a pair episode / valid contact data; rolling / sliding are determined by relative velocity and angular velocity at the contact point, support/contact, and hysteresis. Thresholds are Tuned and require fixtures; they are not physical constants. Formally maintained in: [Event Model](../../10-sound-behaviors/EVENT_MODEL.md) and [Bridge](../../10-sound-behaviors/PHYSICS_AUDIO_BRIDGE.md).
- Data: Add separate draft version1 contracts / asset registry / bindings / record refs, without yet changing existing SceneSpec v1 fields or the old AI 12-tool enum. Host migration / command validation / atomic apply / inverse and the formal renderer remain to be implemented. Valid JSON still requires domain, registry, revision / capability / budget checks; arbitrary JS rules are prohibited.
- Audio: Continuous instances persist and one-shots may overlap; contact sound sources are positioned in the contact region rather than always at COM. Reuse existing clock / absolute delay / path IDs / HRTF and distance attenuation policies; do not create a Behavior→master shortcut for 3D sound.
- Experiments: Distinguish acoustic A/B (fixed emitted signal) from behavior A/B (explicit changes to content / gain / pitch / profile); the latter fixes motion / raw physics-player events / listener / solver / medium and cannot masquerade as changing only acoustic materials or use music to infer RT60.
- Priority: First fill Audio Event Runtime prerequisites; the minimum P0 is AlwaysOn + OnImpact, bounded gain/pitch + unified propagation + a simple Inspector. OnGrab / OnThrow and WhileAirborne unlock according to FPS / interaction prerequisites; do not skip the existing collision / audio continuity / genuine Meta integration mainline to demonstrate new rules.
- Risks: Contact storms, excessive voices/paths, incorrect A/B, shared profile revisions, missing assets, clock / replay inconsistency, and AI-fabricated IDs / measurements. See [Validation](../../10-sound-behaviors/SOUND_BEHAVIOR_VALIDATION.md) and [Limitations](../../KNOWN_LIMITATIONS.md).
- Not superseded: The core authority of ADR-002/004/005/006/007/008/009/011 remains unchanged; this adds a bridge and authoring data layer, not another physics/acoustics solver. See ADR-013 separately for Codex development policy.
