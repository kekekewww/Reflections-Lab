# Performance and buffering optimization roadmap

Date: 2026-11-01 (Asia/Taipei). Status: **PROPOSED / inactive**. The primary baseline is `05d40fd2d52f4b737f6acac61fa00356403c0038`. This round delivers research, evidence classification and future tasks. It implements none of these optimizations, changes neither the original load nor formal performance thresholds, and changes no product code or effective ADR. Completing the research task does not complete V1.

<!-- english-original-anchor --> <a id="先做能辨認原因的工作"></a>
## Start with work that can distinguish causes

First prioritize attribution in 001 and baseline/device capabilities in 014. Use the results to select narrow changes to recording evaluation in 002 and native update responsibilities in 003. Reported stutter is a real symptom; “all computation runs on one thread” is not an established diagnosis. The native Web Audio graph, ordinary acoustic Worker, seal Worker, single in-flight batch, FIR cache, dual filter banks and asset store already exist. Do not rebuild them from scratch.

Preserve the negative R17 numbers on the [formal performance page](../11-v1/BROWSER_PERFORMANCE.md). Its sources/environment are not this baseline. Separate initial uncommitted R21, regression repair and the last dirty observation; early short profiles cannot be attributed to the final source. Recheck before integration. The [audio review](AUDIO_GRAPH_DSP_REVIEW.md) details these boundaries; the [risk register](RISK_REGISTER.md) lists required proof. A research profile using new Chrome lacks the original entry's qualification. Lower voices/paths, changed sampling windows or post-window drain cannot produce a PASS for the original profile.

Ranking combines user impact, evidence strength, expected benefit, cost, risk, dependencies and ease of rollback. It does not score guessed speedups. Benefits are unmeasured candidates, without schedule or improvement-percentage commitments.

## Adoption and validation gates

1. **Baseline gate:** 001/014 P0 capture real source, bundle, browser qualification/version, hardware, power/thermals, viewport/DPR, scene/assets/voice/path counts and device information. Unavailable fields remain UNKNOWN/null. Preserve formal qualification rejection separately from research profiles.
2. **Correctness gate:** Fixed traces and independent oracles first establish ticks, events, revisions, pre-state, source phase, exactly-once delay, path origins and tails. Any persistent format/hash/schema change requires a separate compatibility/migration proposal.
3. **Benefit gate:** At identical load, report compute, copies/dispatch, consumers, native control, CPU/GPU, p95/p99/max, steady/peak memory, queue age and actual output. Reduced control cost with worse latency/quality is not an unqualified success. Unsupported and unmeasured fields remain explicit.
4. **Lifecycle gate:** Each candidate runs 014 P1 pause/resume/seek, background/freeze/sleep, quota, cancellation, worker/context loss and disposal. Recovery identifies last accepted/persisted/published ticks; incomplete work is not Captured.
5. **Adoption gate:** Propose adoption/ADR changes only after independent review, regression and recovery evidence. Future explicit task operations change BACKLOG state. This round performs no automatic optimization, service activation, paid API, push or deployment.

A 600-second wall profile separately reports simulated seconds and captured frames. The current 18,000-frame ceiling is roughly 300 seconds at 60 Hz, with bytes possibly exhausted sooner. Short successful captures inside a 600-second window are not continuous 600-second capture. Normal 100% display is the current scope; 200% is not a required human gate. Hi-x65/D3V listening, material reflection and other unverified items retain their existing states.

Integration follows the [review contract](REVIEW_CONTRACT.md). A dirty target receives a reviewed documentation Patch without stash/reset/overwrite/merge. Preserve Wiki events; reconcile sources and dates before rebuilding indexes, English mirrors and hashes. A reviewable research branch/document set does not complete the product.

Geometry/payload candidates follow the [pose-aware proposal](proposals/ADR-PERF-04-worker-communication.md): geometryRevision currently equals sceneRevision; moving objects require world-surface rebuilding by pose or keys containing the full transformed content. Freeze a finite baseline/candidate list when014 is activated. Later candidates reuse its method and retain results in their own tasks, without continuously expanding or reopening014 completion.
