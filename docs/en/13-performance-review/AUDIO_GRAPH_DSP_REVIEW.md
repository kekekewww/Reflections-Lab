## 1. Conclusion and evidence scope

The product renders through native Web Audio nodes. The main thread still initiates control updates, consumes solver replies and updates AudioNodes/AudioParams; see the API thread/control-message model in [W3C §2.2–2.3](https://www.w3.org/TR/2021/REC-webaudio-20210617/#control-thread-and-rendering-thread). Neither “all samples are computed on the main thread” nor “an audio thread makes the main thread irrelevant to sound” follows. Stable path identities, decoded asset reuse, a FIR response cache, dual filter banks, fades, separate budgets and cleanup already exist. The next step is to attribute remaining control, graph and device costs, rather than propose those existing capabilities as new work.

The reported stutter is an actual symptom awaiting attribution; this study has not established its particular cause. `lateEvents`, stale frames, voice/path rejection, PCM gaps, native output underruns, Worklet execution deadlines and hearing results are different evidence. This page read code, existing receipts and official sources. It **did not rerun the final R21 repair audio harness, offline PCM tests or human hearing tests**. The coordinator separately runs a non-formal600-second study of the committed05d40 baseline; see the [measurement plan](MEASUREMENT_PLAN.md) and [final report](FINAL_REVIEW_REPORT.md). That study cannot replace retesting the final R21 bytes. Tests mentioned here describe existing coverage, not a new PASS.

This extends, without duplicating, the [20261029 browser study](../12-architecture-review/BROWSER_PERFORMANCE_RESEARCH.md), [acoustic core study](../12-architecture-review/CUSTOM_ACOUSTIC_CORE_RESEARCH.md), [Sound Behavior study](../12-architecture-review/SOUND_BEHAVIOR_RESEARCH.md) and [ADR-015](../02-architecture/adr/015-client-first-and-render-contract.md). Existing Worker, transferable, SAB and offline-render candidates do not thereby become accepted implementation decisions. [PERFORMANCE_BUDGET](../06-validation/PERFORMANCE_BUDGET.md) remains authoritative for performance numbers.

## 3. Actual audio graph and clocks

```text
source -> optional content lowpass -> contentGain -> envelope
  envelope -> rawMix
  envelope -> stable direct/early PathRoute -> simulatedMix
  envelope -> earliest-path late PathRoute -> LateReverbBus -> simulatedMix
rawMix + simulatedMix -> runGain -> headroom -> monitor -> muteGain
  -> optional DynamicsCompressor -> optional product WaveShaper -> destination
PathRoute: Delay -> two FIR Convolver/Gain banks -> pathGain -> HRTF Panner
```

- [Engine](../../../src/audio/engine.ts) L68, L133, L154–190: a product-owned context uses `latencyHint: interactive`; no product `audioWorklet.addModule`/`registerProcessor` route was found. The silent processor in `tests/browser/device-hearing/hearing-probe.mjs` only observes block sizes. It is not the product mixer or a deadline profiler.
- The same file, L206, L778, L862–909: `audioEpoch + emission - simEpoch` schedules source onset. Starts over 1 ms late increment `lateEvents` and actually use `max(currentTime, requested)`. Only the route DelayNode adds absolute propagation delay. Missed samples of a late emission are not reconstructed; physical delay is not scheduling slack.
- [Runtime](../../../src/app/runtime.ts) L1034–1059: the primary baseline rejects a whole solve batch if any result is older than three ticks. Pending native voices wait for an available frame. This can delay onset, but does not directly prove a sample underrun in an existing continuous loop.
- Product graph options are in [runtime](../../../src/app/runtime.ts) L1894–1897: unity monitor, 0.5 headroom and outputSafetyClip. Engine defaults differ; measurements must record actual host options.
- Engine L203–371, L1255–1329: pause keeps the context running, makes an interrupted boundary with a 20 ms fade and saves logical cursors and finite pending-arrival segments. Resume rebuilds native sources. This is not sample-continuous restoration of original source/filter state. Source position integrates authored pitch; it is not a hardware playhead.
- Engine L1417–1470 exposes sample rate, base/output latency and propagation responsibility. Native HRTF/limiter latency remains null. These fields do not sum to calibrated ear latency.

## 6. Voices, scheduling and virtualization

[Logical admission](../../../src/audio-behavior/voice-admission.ts) L14–46 sorts by priority and stable IDs, counts every non-stopped instance including fades, and explicitly rejects. [Runtime](../../../src/app/runtime.ts) L397–398 configures 16 logical voices/eight per object; the standalone evaluator defaults to 32. Native [engine](../../../src/audio/engine.ts) L743–808 separately validates assets/references and pending/source/retiring budgets, and can fade/steal a lower-priority native voice. Logical, native and solver outcomes must remain separate; one voice count is insufficient.

Each native sample start creates a new AudioBufferSourceNode (L830) and reuses the decoded AudioBuffer. A continuous loop stays on its source during the same instance instead of rebuilding for grabs or collisions. Natural endings, stops and steals retain route tails before cleanup. There is no virtual-voice system that preserves logical time while suspending expensive acoustic rendering and later restores phase. Pools can reuse assets, DTOs or management slots, not restart an already-started AudioBufferSourceNode; see [MDN lifecycle](https://developer.mozilla.org/en-US/docs/Web/API/AudioBufferSourceNode).

**PROPOSED AGD-05** studies virtualization only if profiling identifies voice/route cost as a bottleneck: define rendered-to-virtual transitions, hysteresis, resume offsets/propagation history, maximum virtual slots and the native admission ledger. Different emitters must not first be mixed at their center of mass. Raw monitoring, interaction triggers, recording/A-B, stem emission selection and priority competition may all be affected. Virtualization cannot delete physics events, recompute recorded logical decisions or pretend omitted paths were solved. Report actual degradation and compare fixed traces; reducing formal workload is not a performance pass.

## 8. Minimum research measurement contract

1. Pin commit or a complete dirty source manifest, bundle/lockfile/browser binary version, actual host audio options, graph topology, context generation, sample rate and device/OS/power route. R21 dirty comparisons require full hashes; `05d40fd` must not stand for different bytes.
2. Separate initial onset, already-running continuous sound, impact bursts, path/shape churn and pause/rebuild scenarios. Save wall, simulation and audio clocks plus pause/overrun/stale/admission timelines. Different simulated durations do not directly establish speedup.
3. Compare uninstrumented native graph, low-rate counters and PCM-tap instrumentation. Save beginning/end cumulative native stats and context recreation/reset boundaries. Deltas require the same supported, monotonic context; unsupported/null stays UNKNOWN. Total cumulative values are not a measurement window.
4. PCM gap classification requires a known continuous reference, fixed thresholds/windows and silence exclusions. Legitimate silence, source stop, fades, occlusion and intentional pause are not the same underrun class. Preserve original PCM and classifier configuration; do not select thresholds afterward to pass.
5. Control traces separately record validated frame age, clone/consume wall time, native node/buffer-set counts, automation events, cache hits/misses and route retirement/timer lateness. Unavailable native CPU/memory stays unknown; JavaScript elapsed time is no substitute.
6. Future graph/automation repairs need meaningful native OfflineAudioContext PCM oracles for arrival, energy, continuity, phase and tails, plus long browser output qualification. Fake contexts prove control requests only. Native API/PCM passes do not imply Worklet p99, headphone localization, SPL or overall V1 completion.
7. Preserve the existing Firefox energy FAIL, WebKit API blockers, R17 formal performance FAIL and earlier negative R21 samples. Save new measurements against unchanged thresholds separately; do not rewrite old results or relax fixtures/tolerances.
