# Native WebAudio Render Trace Capability Verification (Source Research, Not Measured)

This review confirmed that the pinned Chromium producer has render-scope events and can conditionally provide thread CPU time. It is therefore unsupported to assert that all native WebAudio CPU is unmeasurable. However, this is only source capability: CPU fields, complete coverage, and identity evidence from this audio trace have not been obtained; `nativeDspCpuMs` **remains null/NOT_MEASURED**. This document does not establish a DSP CPU, deadline, probe overhead, hardware listening, or 600-second qualification pass.

## Confirmed CPU Semantics

- Chromium's legacy TraceConfig conversion explicitly sets thread-time sampling=true and timestamp multiplier=1000 (L802–833); track-event adaptation also enables sampling when unspecified (L190–201). This proves configuration capability, not validation of raw event fields. [TraceConfig](https://chromium.googlesource.com/chromium/src/+/861389936bf33ea77529ee5dcc0605e68f6bb620/base/trace_event/trace_config.cc#802); [AdaptTrackEventConfig](https://chromium.googlesource.com/chromium/src/+/861389936bf33ea77529ee5dcc0605e68f6bb620/services/tracing/public/cpp/perfetto/perfetto_config.cc#190)
- Perfetto defines thread time as CPU time accumulated by that thread since creation; it reads counters and emits deltas only with sampling enabled and events on the current-thread track. Subsampling can leave individual events missing values. [TrackEventConfig L87–100](https://chromium.googlesource.com/external/github.com/google/perfetto/+/403906f4adfbf287a02e5546f8430dcc9d56b649/protos/perfetto/config/track_event/track_event_config.proto#87); [producer L598–614](https://chromium.googlesource.com/external/github.com/google/perfetto/+/403906f4adfbf287a02e5546f8430dcc9d56b649/src/tracing/internal/track_event_internal.cc#598)
- The Windows non-ARM64 branch converts QueryThreadCycleTime using a calibrated TSC frequency; the ARM64 branch uses kernel+user GetThreadTimes. This research has not established actual sampling success rate or error on this machine. [Windows implementation L126–159](https://chromium.googlesource.com/external/github.com/google/perfetto/+/403906f4adfbf287a02e5546f8430dcc9d56b649/src/base/time.cc#126)
- JSON `ts/dur/tts/tdur` are integer **µs**, obtained by dividing ns by 1000; `dur` is wall duration. Completed positive-duration thread slices can emit `X/dur`; `tts/tdur` additionally require actual thread-time data. Unfinished slices emit `B`; duration must not be invented. Missing `tdur` is unknown, not 0, and cannot be replaced with `dur`; even an actual 0 remains subject to integer-µs quantization. [export L799–804](https://chromium.googlesource.com/external/github.com/google/perfetto/+/403906f4adfbf287a02e5546f8430dcc9d56b649/src/trace_processor/export_json.cc#799); [export L851–914](https://chromium.googlesource.com/external/github.com/google/perfetto/+/403906f4adfbf287a02e5546f8430dcc9d56b649/src/trace_processor/export_json.cc#851)

`TRACE_EVENT` closes the slice on leaving scope. Each layer below is therefore inclusive; do not sum parent/child CPU durations or subtract child wall duration from parent CPU duration. These calculation restrictions follow from scope and the semantics of the two clocks; actual nesting/tid still require raw-trace verification. [Scope macro L391–393](https://chromium.googlesource.com/external/github.com/google/perfetto/+/403906f4adfbf287a02e5546f8430dcc9d56b649/include/perfetto/tracing/track_event.h#391)

## Future Measurement Hooks and Required Evidence

A separately versioned diagnostic method could use candidate categories `webaudio`, `disabled-by-default-webaudio.audionode`, and `disabled-by-default-audio-worklet`. **This review changed no formal category or qualification registry.** The formal category list at `performance-profile-v3.mjs:783–798` currently excludes these WebAudio categories, so the original trace cannot be presumed to cover audio rendering.

Before actual measurement, require:

1. An exclusive machine lease and explicit method version; preserve the original 600-second wall workload, voices, paths, geometry, capture load, qualifications, thresholds, and original rejections. A short trace is not formal 600-second evidence.
2. browser/revision, executable path+SHA, hardware/OS/architecture, actual device/rate/buffer/quantum, source archive, context/document lifetime, and exporter pins. Do not infer 48kHz/128 frames from event names.
3. The entire raw stream, loss/closure, event category/name/schema, original ordinals, pid/tid, and context/graph attribution; exact measurement windows and completed scopes, retaining unknown/unfinished events. Do not trim traces to obtain PASS.
4. Actual `tts/tdur`, finite nonnegative values, required endpoints, and CPU coverage. List sample/missing/unfinished counts, quantization, and units; source defaults do not automatically make coverage complete.
5. First report verified inclusive output callback/context render/Worklet scopes; without independent complete separation evidence, do not rename these values native-exclusive DSP. Do not arbitrarily subtract parent/child values across threads.
6. A same-condition probe-free/probe-on comparison quantifying disturbance from tracing and the PCM tap; this source research measured no overhead.

Product `src/audio/diagnostics.ts:88–92,318–322` and the attribution output's `nativeDspCpuMs` currently remain null. If inclusive render CPU can later be measured, first output it under a precise new scope name, then use independent validation to decide whether it meets native DSP field semantics; do not fill values before supplying evidence.
