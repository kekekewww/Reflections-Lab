# Pinned Producer Semantics for a Single Bootstrap Timer Event

Status is SOURCE_AND_EXISTING_RAW_REVIEW_ONLY. Checked Chromium 861389936bf33ea77529ee5dcc0605e68f6bb620 and Perfetto 403906f4adfbf287a02e5546f8430dcc9d56b649 pinned by its DEPS; no new Node, test, browser, build, or 600-second measurement was run, and original frozen sources/original FAIL were unchanged.

The existing close timer in attempt02 directly confirms fields: original ordinal 2316 is TimerInstall, devtools.timeline, I/s: t, with data timerId=1, frame, timeout=0, singleShot=true. ordinal 2330 is TimerFire, X/dur=5582 us, with data containing only timerId and frame; the enclosing complete ThreadControllerImpl:: RunTask at ordinal 2329 starts at 954578569 us, dur=5591 us. These are existing close timers, not evidence that the new bootstrap ran successfully.

The [DOMTimer producer](https://chromium.googlesource.com/chromium/src/+/861389936bf33ea77529ee5dcc0605e68f6bb620/third_party/blink/renderer/core/scheduler/dom_timer.cc#361) emits Install after scheduling and encloses the firing lifecycle with scoped Fire. A zero timeout selects an immediate timer task when the nesting clamp does not apply; it represents the requested timeout, not an actual scheduling delay of 0. Actual delay still requires a separate callback-entry minus request-time measurement.

The [Timer data producer](https://chromium.googlesource.com/chromium/src/+/861389936bf33ea77529ee5dcc0605e68f6bb620/third_party/blink/renderer/core/inspector/inspector_trace_events.cc#988) writes timerId and writes frame only when LocalFrame exists. Install additionally writes timeout. InMillisecondsF() and singleShot. This Window fixture should require the correct frame; timer payload has no navigationId, so it must not require a nonexistent field. Timer IDs belong to execution contexts; a matching ID in another frame cannot be borrowed.

SetCallStack at lines 130–147 of the same file adds sampleTraceId and possibly stackTrace only when disabled-by-default-devtools.timeline.stack is enabled. The existing pinned includedCategories list has five complete entries: devtools.timeline, blink.user_timing, toplevel, v8, disabled-by-default-devtools.timeline.frame; disabled-by-default-devtools.timeline.stack is disabled. Thus the current exact four Install data fields have explicit conditions; a future category change requires a new version, rather than accepting arbitrary extra fields.

The [UserTiming producer](https://chromium.googlesource.com/chromium/src/+/861389936bf33ea77529ee5dcc0605e68f6bb620/third_party/blink/renderer/core/timing/performance_user_timing.cc#87) saves physical callTime separately from requested startTime; [TimeTicks trace conversion](https://chromium.googlesource.com/chromium/src/+/861389936bf33ea77529ee5dcc0605e68f6bb620/base/trace_event/traced_value_support.h#128) confirms callTime is microseconds, while startTime is milliseconds on the performance clock. Window marks' [navigationId comes from LoaderId](https://chromium.googlesource.com/chromium/src/+/861389936bf33ea77529ee5dcc0605e68f6bb620/third_party/blink/renderer/core/timing/performance_timing.cc#314). Mark tracing may also collect a V8 sample, so its cost cannot be treated as zero.

New bootstrap validation should require a unique owned Install→complete Fire→two auxiliary marks, with actual timer handle, pid/tid, frame, and loader identity all matching. Each mark's physical callTime must lie within Fire, which must lie within a complete native RunTask accepted by original V3 and within the original time window. Do not synthesize RunTask from auxiliary marks or TimerFire; missing complete task, delay beyond the original 50 ms, wrong owner/category/navigation, duplicates, or unfinished events must all be rejected.

Auxiliary marks must avoid the rlab-v3.observe prefix. A single real task can verify original edge coverage while preserving original begin/end, but does not recover lost CPU from the resume task or prove that the entire window has no other omissions. See the same-named JSON for complete code SHA256, line numbers, acquisition status, and original events; official full texts were not copied into the repository.
