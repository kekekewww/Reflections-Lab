# UI/UX and Shared State Review

Review date: 2026-10-29 (Asia/Taipei). Code baseline: `c210ca882ca8503b322c28884bf1e9f6e9fe126d`; this document is a **STATIC REVIEW / research recommendations**. No new human task testing, visual, keyboard/mouse or audio operation, or performance measurement was performed. Code review, token checks and reading competitor documentation must not be reported as a browser visual PASS. This report does not redesign the interface, change canonical tokens or treat new recommendations as accepted requirements.

<!-- english-original-anchor --> <a id="1-判斷"></a>
## 1. Assessment

Keep the current three workspaces and single domain runtime. First improve **consistency of selection, the currently effective Listener and the operation target**, then organize the information hierarchy and the entry points within each mode. There is no evidence supporting a complete layout rebuild. Objects, physics mode, listener pose, run/recording and acoustic results must share authoritative data. Panels may own local drafts and expanded/collapsed state, but must not maintain conflicting copies of physical truth.

The current `App` supplies Explorer, Viewport, Inspector and AnalysisDock with the same `useSyncExternalStore` model, and sends `LabAction` to the domain runtime. Authoring object DTOs are separate from runtime interpolated poses, and the Inspector already labels authoring settings. Preserve these foundations. See [App](../../../src/ui/App.tsx), [contracts](../../../src/ui/contracts.ts), [runtime](../../../src/app/runtime.ts) and [view projection](../../../src/app/view-projection.ts).

The earlier human report described unusable first-person interaction and a confusing UI. Component browser repair evidence exists from later work, but normal 100% human FPS/Pointer Lock/IME testing and listening on the specified devices still await actual results. The historical report must not be described as a failure that necessarily reproduces in the current version. The complete V1 remains unfinished, and the negative formal 600-second performance result is retained. The required 200% human gate was removed by the [acceptance amendments](../11-v1/ACCEPTANCE_AMENDMENTS.md); do not add it back.

## 3. Shared State and Ownership

| Data | Current authority/presentation | Recommendation and boundaries that must remain distinct |
| --- | --- | --- |
| Authoring objects/physics settings | SceneDocument plus revision, `patchObject`/scene command; ObjectView is a projection. | Explorer, Inspector and any new Motion view must use the same object ID. Do not store independent mode/mass copies in Motion. |
| Runtime pose/velocity | PhysicsWorld fixed step; `getPose` supplies render interpolation; velocity/held/sleeping are read-only projections. | Moving objects must not silently change their starting values in the Inspector's authoring position. “Save as initial state” requires a separately explicit transaction. |
| Object selection | `model.selectedObjectId`, a stable ID; deleting the selected object clears it, and Undo does not silently select another object. | Preserve the existing regression. Do not identify objects using a list index, Rapier handle or sort rank. |
| Listener selection | The Listener pose is in the runtime, but displaying the Listener Inspector is currently controlled by App-local `showListener`; selecting the Listener clears object selection. | First consider a shared presentation adapter and consistent selected semantics; evaluate typed `object/listener/environment/path/event` selection later. The existence of a boolean alone is not a runtime bug. |
| Effective Listener/observer camera | Scene listener, FPS attachment and replay listener each obtain their values from the runtime; the editor camera is separate. | Display whether the source is the authoring Listener, FPS head or recorded trajectory. Frame selected/the observer camera must not silently move the measurement receiver. |
| Event/path selection | `selectedEventId`/`selectedPathId` are resolved against the actual event/path collections. | Preserve an invalid/stale indication when a path disappears. Do not substitute the first path after a new sort for the original selection. Any future typed selection must carry the run/frame. |
| Workspace/layout | The runtime manages workspace; panel widths/hidden/mobile pane are App-local state. | Workspace changes must not reset a run. Layout preferences may later be saved per workspace. Do not rebuild the engine when changing workspace. |
| Recording/results | RecordingHost, immutable artifacts and run/scene/method pins. | Recording playback cursor, authored motion and audio monitoring use different clocks. Results reference a fixed run and must not read only the current Inspector. |

Code and tests: [stable selection](../../../tests/app/selection-stable-id.test.ts), [narrow Listener DTO](../../../tests/app/listener-projection.test.ts), [record/replay](../../../src/app/recording-host.ts) and [result tools](../../../src/app/experiment-tools.ts). Shared state does not require placing every high-frequency engine object in React state. Keep fixed-step execution, interpolation, solver and audio clocks separate.

## 4. Review by Area: Before/After/Why

Every “After” item is a recommendation awaiting evaluation. It does not mean this research changed the product or passed usability testing.

| Area/Before (code observed in this review) | After (PROPOSED) | Why/how to validate |
| --- | --- | --- |
| Workspace: Scene/Simulation/Analysis and shared Run/Pause controls already exist; local panel preferences use one shared set of state. | Preserve the information architecture. Only when actually needed, let each workspace remember its panel configuration and observer camera. | A workspace is a task view; switching must not reset a run/recording. Validate switching while Running and the safe pause flow for a held object. |
| Explorer: object rows have a selected class/aria-pressed; the Listener row has no corresponding selection presentation (baseline `SceneExplorer.tsx:79/81/112`). | Minimal repair candidate: pass presentation state indicating whether the Listener is being shown, and add consistent selection styling plus accessible naming/pressed semantics. Remove the temporary adapter only after entity selection is unified later. | Users should know whose data the Inspector shows. Change presentation without redesigning the domain. Inspect the actual 100% view, keyboard operation and object↔Listener switching; STATIC REVIEW cannot replace this. |
| Viewport: R3F/input controls have a stable lifecycle; includes actual solver paths, frame selected, FPS entry and error/fallback states. | Keep the scene prominent. Show only the current mode's main operations in the main view; retain expandable diagnostics and complete limitations. | Reduce density while retaining inspectable provenance. Do not remove Mute/Pause/exit/failure reasons to make the view “clean.” |
| Inspector: authoring transform is already labeled as authoring settings; editing is prohibited while running/replaying; rules/bindings have local drafts and revision guards. | Preserve this separation. Use real task tests to check whether the current object's name, ID and authoring/runtime labels are immediately distinguishable. Reveal advanced frequency/hash/mapping details progressively. | Avoid mistaking the currently displayed pose for the starting value. First verify that primary operations can be found; do not add another complete parallel form. |
| Motion: physics operations, recording and replay/seek exist; no formal MotionAction editor or CreateMotionAction tool was found. | If separately accepted as new scope, add a motion section for the selected object that clearly distinguishes authored action, runtime pose and recorded trace, using shared selection and physics mode. | A timeline's appearance does not prove motion reproducibility. The domain validates kinematic clearance/trace pins. Existing recording is not a general keyframe authoring tool. |
| HUD: held/ghost/mode states and controls without pointer lock are available; clickable Grab/Release/Throw/Place entry points exist. | Highlight only the current primary action for Idle/Holding/Build/Staged; retain expandable alternative controls and the actual input owner. | These provide alternatives for pointer-lock or interaction barriers and should not all be deleted as redundant. Test Esc/blur/IME, consumption of the lock re-entry click without throwing, and workspace switching while holding an object. |
| Timeline: the Events tab has record start/stop, replay, export, a slider and stable event selection. | Clearly label recording/replaying/saved/interrupted. Show the cursor's run and recorded time; selecting an event should locate the same object/contact evidence. | A recording with gaps or without finalization is not a complete result. An event timeline cannot establish audio-device onset. |
| Acoustic: paths, metrics, capability/freshness, unsupported reasons and comparison exist. | Show available results and necessary reasons first, followed by expandable run/source/listener/band/method/units details. Keep the same path ID in the table, 3D view and details. | Distinguish `0` from null, stale from empty, and Computed from Measured. IR cannot yield individual paths, and a finite path set cannot fabricate RT60. |
| Render: no CreateRenderJob schema/executor/UI was found; live monitoring, static preview and JSON export exist. | If offline rendering is added, first define fixed scene/motion/listener/output specifications and job states, then design the Render panel. | Palette/AI: AI currently occupies one AnalysisDock tab, with offline/Meta gates and preview/Apply/Cancel; no separate global Command Palette was found. | Preserve the working entry point. If a global palette is added, use it mainly to search for and navigate to existing actions, without rebuilding Physics/Listener/Behavior state. | UI/IME owns input while the Palette is open. Closing returns focus to its trigger without automatic lock/resume. Errors retain the prompt; a loading state must not imply everything is cancellable. |
| Monitor: global Mute/gain/Raw–Simulated and context state exist; static preview has separate metadata. | Continue making the source explicit: dry reference/simulated monitoring/static preview/recorded replay, with an accessible current Mute control. | Preview, active computation, audible audio and artifact success are separate dimensions. Changing modes must not raise source gain or change experimental values. |

## 6. Types of Redundancy and a Minimal Change Strategy

| Type | Recommended treatment | What should not be done |
| --- | --- | --- |
| Multiple entry points for the same action that serve keyboard/without-pointer-lock alternatives | Keep the same LabAction, group or collapse by mode, and use consistent labels/disabled reasons. | Delete Grab/Throw buttons merely because shortcuts exist. |
| Multiple views of the same data, such as Explorer/Viewport/Inspector | Keep linked views sharing stable identity and domain DTOs. | Require a single remaining view or create another physical truth. |
| Multiple complete editors for the same setting | New Motion/Palette areas should navigate to existing controls or reuse the same component, editing only necessary parameters locally. | Build separate Listener/mode/source forms with different commit rules in every panel. |
| Persistent technical evidence makes the view crowded | Expand hashes/full limitations/method details on demand; keep necessary current errors/stale/unsupported status at the point of operation. | Hide failure reasons that affect decisions or turn unknown states into green lights. |
| Authoring pose and runtime pose appear duplicative | Keep both and state their purposes; runtime is read-only, while authoring fields use Undo commands. | Deduplicate by writing the current physics pose back into SceneDocument. |

The smallest candidate is consistent Listener-row selection semantics and the current Inspector target. It does not change the solver, physics, schemas or audio clocks. Full typed selection, per-workspace preferences and Motion/RenderJob/Palette are later architecture work, beyond this review's minimal adjustments.
