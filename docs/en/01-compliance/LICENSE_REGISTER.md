## Local Optional Skill Validation Tool

`PyYAML==6.0.3` is installed only in the ignored `.cache/skill-validation/` for skill frontmatter validation; it is not a product dependency, part of the npm count, or a redistributed binary. Both the official [PyPI 6.0.3](https://pypi.org/project/PyYAML/6.0.3/) page and [pinned-version LICENSE](https://raw.githubusercontent.com/yaml/pyyaml/6.0.3/LICENSE) confirm MIT; local `pyyaml-6.0.3.dist-info/METADATA`, `licenses/LICENSE`, and `WHEEL` were read. The metadata author is Kirill Simonov, while LICENSE lists copyrights for both Ingy döt Net and Kirill Simonov; the full notice must be retained if copied / distributed in the future. This wheel's tag is `cp312-cp312-win_amd64`; it is not claimed to be pure Python or to have completed a distribution audit of every binary component.

The host Python originally lacked yaml / pip, so pip 26.2.1 from the Codex bundled Python was used with a specified workspace target; nothing was installed globally and the host Python was not modified. The following commands reconstruct the same version in the same isolated location; they are not product installation steps. The bundled path was confirmed by `load_workspace_dependencies`; other machines should first obtain their corresponding path again.

```powershell
$skillValidationPython = 'C:\Users\kevin\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
& $skillValidationPython -m pip install --target '.cache/skill-validation' 'PyYAML==6.0.3' --disable-pip-version-check
```

The SHA-256 hashes of the local metadata / LICENSE are recorded in the inventory's `optional_local_tools`, separately from the 88 npm packages; this work did not add the PyYAML wheel, C extension, or installation directory to Git.

## Registration and Distribution Gates

For each adopted asset, record `asset_id`, original author, official URL, version / commit, acquisition UTC, SHA-256, location of the original license text, modifications, purpose, distribution scope, required attribution, and competition status. Do not record only the package's SPDX abbreviation while omitting original text and third-party components.

`package-lock.json` is the source for reproducible dependencies; [DEPENDENCY_LICENSE_INVENTORY.json](../../01-compliance/DEPENDENCY_LICENSE_INVENTORY.json) (schema 2) is a snapshot of metadata / license file hashes for locally installed packages, also recording lockfile integrity and separate optional local tools. Its results are not legal approval and do not determine all rights in every file. A future public build requires a new inventory based on the actual bundle / native linkage / data files, distribution-ready `THIRD_PARTY_NOTICES`, and a check of what the competition accepts.

The historical Phase 1 snapshot has 88 installed packages: 61 MIT, 14 Apache-2.0, 6 BSD-2-Clause, 2 BSD-3-Clause, 4 ISC, and 1 BlueOak-1.0.0; all have a manifest license field. For some packages, a root-level license filename scan found no matching file; they are marked `license_files: []`, which means only `ARTIFACT_NOT_DETECTED`. README files, embedded headers, or upstream distributions may need checking; this does not establish that there is no license or that notices are waived.
